# Project review rules

针对本次 PR 引入或暴露的真实问题审查，结合需求、调用路径和项目约定判断。
不要仅凭个人风格偏好要求重写；不要把“未发现问题”解释为完整正确性保证。

## Blocking findings

- P0：广泛且严重的故障/数据破坏，需要立即处理。
- P1：常见或关键路径上的确定性错误，或可利用的权限/安全问题。
- P2：有明确触发条件的功能错误或回归，需修复或由人明确接受。
- P3：非阻断建议，不因格式、命名偏好或一般性优化阻止交付。

优先查看输入边界、错误/取消路径、并发与资源释放、权限边界、数据一致性、
兼容性和与变更相关的测试断言。只有与实际变更相关时才展开这些检查。
涉及迁移、支付、认证或公共协议时，明确指出影响范围、兼容/回退假设。

## Evidence

每项发现给出：优先级、文件和最小行范围、触发条件、影响，以及可验证的例子或测试建议。
证据不足时明确假设或待确认信息，不把猜测写成确定缺陷。
检查测试是否断言真实结果，是否通过删测试、跳过断言或修改门禁掩盖失败。
审查结论针对实际审阅的版本；新推送需重新核对。

## Scope

本规则指导审查内容，不能直接改变 GitHub 分支门禁或 Bugbot 检查状态。
未经任务明确要求，不扩大范围到无关重构或全仓审计。
